# Minecraft Art Direction

## Purpose
Translate a vague mood into a visual system that can guide every model, texture, icon, animation and scene.

## Trigger
Use when starting an asset collection, defining a server/resource-pack identity, matching vanilla or a named stylized direction, or correcting inconsistent assets.

## Inputs
Audience and gameplay role, target Minecraft edition/runtime, vanilla or custom style target, reference images, asset categories, technical limits, and existing assets.

## Workflow
1. Define the style target: vanilla-compatible, faithful extension, stylized, cartoon, fantasy, sci-fi, dark, cute, realistic voxel, or hybrid.
2. Define shape language: chunky/slender, rounded/angular, organic/geometric, simple/ornate.
3. Define silhouette rules and readability at actual in-game size.
4. Define palette roles, value range, light direction, outline policy, material language, and detail density.
5. Define model complexity and texture resolution per asset class.
6. Create a one-page style card with do/don't examples and reference swatches.
7. Apply the style card to one representative asset before scaling production.
8. Review assets side-by-side; update the style card when a justified exception is accepted.

## Safety and rights
Use user-authorized references. Record source and license for external assets. Do not reproduce a living artist's exact style; translate requests into broad visual attributes.

## Outputs
Art-direction brief, style card, palette roles, shape/material rules, asset-specific constraints, and review checklist.

## Failure handling
If references conflict, identify the conflict and propose a primary direction plus explicit exceptions rather than blending everything indiscriminately.

## Acceptance criteria
A second creator or AI agent can use the style card to create a new asset that visibly belongs to the same set. Evaluate using a side-by-side asset sheet, not prose approval alone.
